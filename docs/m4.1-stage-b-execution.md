## 4. A→B upgrade — failed

Release B was registered as beta, CP release id 2. The upgrade started at
**08:20:12** and failed at **08:20:25**.

- CP result: `status: failed`, `error: coolify_deployment_failed`.
- Coolify deployment `ikbmlcepcrjd5the9mpjxgnr`: `failed`.
- Store app ended `exited:unhealthy`, image fields:
  `ghcr.io/hoosainmadhi/vula-pos-store` + tag
  `72a9aeb896d4aa6bdb570e696f9b51b6954acd981a6fe304c3bd18ee6a585cb5`.
- Stop-first worked: the container monitor took 129 samples around the upgrade
  and never saw more than **one** Store container; no B container started.
- Database volume remained mounted and intact.

### Root cause

`src/services/coolify.ts` `updateApplicationImage()` sent:

```text
docker_registry_image_name = ghcr.io/hoosainmadhi/vula-pos-store
docker_registry_image_tag  = <digest hex>
```

Coolify therefore attempted to pull `<repository>:<digest-hex>`, which does not
exist. A digest release must use `<repository>@sha256` as the image name and the
hex digest as the tag. Initial provisioning happened to work because it used the
full digest reference; the upgrade path lost the `@sha256` marker.

### Repository fix deployed

`updateApplicationImage()` now sets
`docker_registry_image_name = <repository>@sha256` and keeps the digest hex in
`docker_registry_image_tag`. A regression assertion checks the PATCH body.

- Full CP suite: **520/520**, 39 suites.
- Typecheck and production build clean.
- The fix was deployed to the staging CP as commit `619f936`; the next CP
  reconciliation failed separately at stop confirmation.
