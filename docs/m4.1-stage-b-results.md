## Remaining reliability note

The CP still checks Coolify’s app status once immediately after a deployment
reaches terminal success. A cold B container can briefly report
`running:unhealthy`, so an otherwise successful upgrade can be recorded failed.
The audited reconciliation path corrects this, but a future fix should wait for
the app’s health status/container readiness before declaring failure. This is a
false-negative verification race, not a two-writer or data-safety failure.
